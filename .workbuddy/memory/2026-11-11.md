## 关键坑（都已实测）
1. `sshd` 首次启动**没有主机密钥** → KEXINIT 的 hostkey 列表为空，客户端报 `no matching host key type found. Their offer: `。修法：`ssh-keygen -A`，路径从 `sshd -T | grep ^hostkey` 读，不要硬编码。
2. 公钥位置是 `/boot/home/.ssh/authorized_keys`（同时写 `~/config/settings/ssh/authorized_keys` 兜底）。
3. sshd 二进制是 `/bin/sshd`。
4. `user` 是 uid=0，被 `PermitRootLogin` 管，必须 `yes` 才能公钥登录。
5. NAT 端口转发用 `controlvm natpf1` 加的是**运行时规则，虚拟机会话结束就丢**；`modifyvm --natpf1` 才是持久的（VM 运行时锁住改不了）。
6. 客户机访问宿主：`10.0.2.2` == 宿主回环。传脚本/文件走这个，不需要外网 paste 服务（dpaste.com 在本机 TLS 校验失败）。
7. `curl https://10.0.2.2:...` 会报 `wrong version number`——那是纯 HTTP 服务，别写 https。
8. 无 Guest Additions，PS/2 相对指针；GUI 自动化不现实，看屏幕用 `VBoxManage controlvm HaikuOS screenshotpng out.png`（截图不含缩放，1:1 对应 framebuffer）。

## 下午补充（同一环境的后续结论）
1. **sshd 卡死的真正原因**：用户在 `pkgman` 里把 openssh 升到了 **10.4p1**，而 sshd 正在跑，二进制被就地替换 → 进程挂住。表现是 TCP 能连上、但收不到 banner（内核 backlog 接了连接，进程不 accept）。
2. **sshd 是开机自启的**（launch_daemon 拉起 `/bin/sshd -D`，PID 112，子进程是 `/packages/openssh-10.4p1-1/.self/lib/openssh/sshd-session`）。所以**重启虚拟机后不需要敲任何命令**，SSH 自己就回来了。别再让用户手动 kill/启动。
3. 升级 openssh 后必须重启虚拟机，否则会复现上面的卡死。
4. **Haiku 没有 `killall`**。杀进程统一用：`for p in $(ps | grep -w X | grep -v grep | awk '{print $1}'); do kill $p; done`。
5. 磁盘：8 GiB，已用 2.6 GiB，剩 **5.4 GiB**（32.6%）。LibreOffice 之类大包能装但会很挤。
6. 包管理器 = `pkgman`（GUI 是 HaikuDepot）。`winget` 是 Windows 的，Haiku 上不存在。
7. `sync-build.sh` 已内置：SSH 不通时自动补 `natpf` 转发规则，仍不通才打印需要用户执行的命令。
8. **用户偏好（重要）**：不要把长命令丢给他粘——VBox 里粘贴很麻烦。优先用一条极短命令、或 dpaste 短链、或由我用 `VBoxManage controlvm keyboardputstring` 直接把内容打进虚拟机（他只要打开终端并让窗口获得焦点）。
9. **`.workbuddy/` 不再被 gitignore**（用户要求：会在不同电脑开发，要同步记忆）。仓库是公开的，记忆里有学校名等个人信息，已提醒他注意。
10. `ssh` 跑远程后台进程必须加 `-n` + `</dev/null` + `timeout`，否则通道不关、客户端挂死。今天因这个把客户机 BFS 写卡死，最后只能 `VBoxManage controlvm poweroff` 硬断电重启（BFS 日志回滚正常，没丢数据）。
11. Haiku `ps` 列顺序是 `Team | Id | #Threads | Gid | Uid`，**PID 在第 2 列**（之前用 `[$1]` 一直杀的是进程名，等于没杀）。
